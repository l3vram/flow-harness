# v0.24 — `@flow/verify`: derive QA criteria from acceptance (the Requirement→Verification node) — self-built

Bridges the planner's free-text acceptance to the QA engine's executable criteria. A new package
`@flow/verify` with one LLM-backed function that turns each acceptance statement into an executable
`Criterion` (a verify command), plus a deterministic parser — offline-testable exactly like `@flow/planner`.
Standalone for now; wiring it into `flow-run` (planner acceptance → derived criteria → orchestrator QA) is a
follow-up.

## Contract
`export async function deriveCriteria(router: ModelRouter, acceptance: string[], context?: string, opts?: { tier?: string }): Promise<Criterion[]>`
- Empty `acceptance` → `[]` (no LLM call).
- Otherwise: `buildDeriveMessages(acceptance, context)` → `router.complete({ tier: opts?.tier ?? "opus", messages })`
  → `parseCriteria(res.text)`. Judgment on `opus`; the parse is deterministic.
- Output `Criterion[]` from `@flow/qa` (`{ id, description, verify: string[], severity?, tags? }`), directly usable
  by `runQA`.

## Files (new package; recon from `@flow/planner` mirrored)
1. `packages/verify/package.json` — name `@flow/verify`, deps `@flow/llm` + `@flow/qa`, no bin.
2. `packages/verify/tsconfig.json` — references `../llm`, `../qa`.
3. `packages/verify/src/prompt.ts` — `buildDeriveMessages(acceptance, context?): Message[]` (import `Message` from
   `@flow/llm`). System: "Turn each free-text acceptance statement into ONE executable QA criterion. Reply with ONLY
   a JSON object `{ criteria: [{ id (kebab-case, unique), description, verify (argv array run with no shell, exit 0
   iff the acceptance holds; e.g. [\"node\",\"-e\",\"…\"], [\"curl\",\"-f\",\"URL\"]), severity?, tags? }] }`. If a
   statement can't be checked by a command, still emit it with `verify: []` (reported pending)." User: the numbered
   acceptance list + optional context.
4. `packages/verify/src/parse.ts` — `parseCriteria(text): Criterion[]`: slice the first `{`..last `}`, `JSON.parse`,
   require `criteria` to be an array, map each → Criterion (id required non-empty; description defaults to id; verify
   = array of strings else `[]`; severity kept only if one of low/medium/high/critical; tags kept if a string[]).
   Throw `"verify: no parseable JSON"` when absent/invalid. Mirror `@flow/planner/parse.ts`.
5. `packages/verify/src/derive.ts` — `deriveCriteria` as above.
6. `packages/verify/src/index.ts` — `export * from "./prompt.js"; export * from "./parse.js"; export * from "./derive.js";`.
7. `packages/verify/test/verify.test.ts` — offline: a scripted router returning `{criteria:[…]}` → `deriveCriteria`
   returns parsed `Criterion[]`; empty acceptance → `[]` without touching the router; `parseCriteria` handles embedded
   prose and defaults a missing `verify` to `[]`; a criterion with no `criteria` array throws.
8. `tsconfig.json` (root) — add `{ "path": "packages/verify" }`.

## Pre-req (I do this before the auto-build)
Create the workspace symlink `node_modules/@flow/verify -> ../../packages/verify` (a new dep on a new package needs
it before `npm test` can resolve the bare import — the v0.19 lesson). `@flow/llm`/`@flow/qa` symlinks already exist.
