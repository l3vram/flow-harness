# Plan v0.34: worktree isolation over MCP + host-facing usage instructions

Planned at commit `253f1ab`, 2026-09-08. Milestone: make `flow_run` safe and self-driving from an
MCP host (opencode) — isolate runs on a branch, and have the server tell the host how to call it so
the user never hand-writes tool params.

## Piece 1 — worktree over MCP (self-built via flow-run)

Today `runFromConfig` (the MCP `flow_run` path) does NOT create a git worktree — it writes into
`targetDir`'s working tree (worktree lives only in the `flow-run` CLI's `main`). For an external
target (e.g. an Android app, not a node monorepo) a worktree is safe and desirable.

- `runFromConfig` honors `config.worktree === true`: when `isGitRepo(targetDir)`, create a worktree
  at `<baseDir>/worktrees/<runId>` on branch `flow/<runId>`, run the orchestrator against it, then
  `commitAll` and surface `branch`/`worktreeDir` on the `RunReport`. Off by default (unchanged).
- `RunReport` gains optional `branch?: string; worktreeDir?: string;`.
- Scope (Piece 1): `packages/orchestrator/src/run.ts`, `packages/orchestrator/src/types.ts`,
  `packages/orchestrator/test/worktree.test.ts` (create).
- Verify: `npm run build && npx vitest run packages/orchestrator`.

## Piece 2 — the server hands the host everything (direct maintenance)

So the user just says "use flow to add X to my app at <path>" and the host fills the params.

- `flow_run` inputSchema gains a `worktree` boolean; the handler passes it through.
- `packages/mcp-server/src/server.ts` sets a server-level `instructions` string (MCP `ServerOptions.instructions`,
  returned in `initialize`) that documents the flow_run workflow: absolute `targetDir`, one-sentence
  `objective`, review-plan-first (omit `acceptPlan`, then `acceptPlan:true`), prefer an explicit
  `verifyCommand` (Android: Gradle) with `deriveCriteria:false`, `worktree:true` for isolation, where
  evidence lands, and the Android Layer-C limit.
- `flow_run`'s tool `description` is enriched with the same essentials.
- A small offline test asserts the `worktree` field and that the instructions mention the workflow.
- Scope (Piece 2): `packages/mcp-server/src/tools.ts`, `packages/mcp-server/src/server.ts`,
  `packages/mcp-server/src/index.ts` (export the instructions), `packages/mcp-server/test/guidance.test.ts` (create).

## Verification (whole increment)

`npm run build && npx vitest run` (all green, +tests), then `npm run bundle` and

## Notes

- Piece 1 is dogfooded by `flow-run` (manual task, full-file writes); Piece 2 is applied directly

- The worktree test needs `git` (init a temp repo with an initial commit; `git worktree add` needs HEAD).
