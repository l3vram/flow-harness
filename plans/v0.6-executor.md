# Plan v0.6 — `@flow/executor` (real executor)

Self-contained execution plan. Cold context assumed; everything is here.

**Repo:** `/Volumes/ExtSSD/mac-storage/projects/flow-harness` — git, npm workspaces, TS ESM
`NodeNext` (explicit `.js` import specifiers), `strict` + `noUncheckedIndexedAccess`, Node 22.
Study `packages/ceo/src` and `packages/llm/src` for style and exact exported APIs.

**Goal:** the keystone that turns a task into real work. Given a task instruction and optional
repository context, the executor asks the model for the full contents of the files to write,
**applies them inside a target directory only**, then runs a **configured verify command** and
reports the result. It is the ONLY component that writes product code.

**Security is part of the spec — do not weaken it:**
- File paths from the model are validated: must be relative, use `/`, and never contain a `..`
  segment or a leading `/`. `applyChanges` additionally guards that each resolved path stays
  inside the target directory (defense in depth).
- The verify command comes from configuration (`ExecutorOptions.verifyCommand`), **never** from
  the model output.
- The executor writes only under `targetDir` and runs only the configured command, so untrusted
  repo/model content cannot escape that blast radius.

Create `packages/executor` = `@flow/executor` (`type: module`, bin `flow-exec`). Deps:
`@flow/llm` and `@flow/context` (workspace `*`). No external runtime deps (Node stdlib only).

## Exact APIs you depend on
- `@flow/llm`: `class ModelRouter` (`complete(req)`), `routerFromEnv(env?)`, `class FakeProvider`
  (`new FakeProvider({ responder })`), types `Message`, `Tier`.
- `@flow/context`: `class ContextEngine` (`static index(root)`, `assemble({ query, tokenBudget })`
  → `{ items: { snippet, path }[] }`). Optional — only used by the CLI.

## Files

### `src/types.ts`
```
import type { Tier } from "@flow/llm";
export interface FileChange { path: string; content: string; }
export interface ExecTask { id: string; instruction: string; }
export interface VerifyResult { ran: boolean; ok: boolean; output: string; }
export interface ExecResult { taskId: string; files: string[]; reason: string; verify: VerifyResult; }
export interface ExecutorOptions { tier?: Tier; verifyCommand?: string[]; maxFiles?: number; }
export interface ExecContext { targetDir: string; context?: string; }
```

### `src/prompt.ts` — `buildExecutorMessages(task: ExecTask, context: string): Message[]`
System message content, verbatim:
```
You are an implementation executor. You are given a task and optionally some relevant repository
context. Produce the complete new contents of every file needed to accomplish the task. Reply
with ONLY a JSON object, no prose, of exactly this shape:
{"files":[{"path":"relative/path/from/root","content":"full file contents"}],"reason":"one sentence"}
Every path MUST be relative to the project root, use forward slashes, and never contain "..".
Provide the FULL content of each file you write, not a diff.
```
User message content: `` `Task: ${task.instruction}` `` and, when `context` is non-empty, append
`` `\n\nRelevant context:\n${context}` ``.

### `src/parse.ts` — `parseChanges(text: string, maxFiles = 50): { files: FileChange[]; reason: string }`
Take the substring from the first `{` to the last `}` and `JSON.parse`; on failure throw
`Error("executor returned no parseable JSON")`. Then:
- `files` must be an array; throw `Error("executor JSON missing files array")` otherwise.
- Throw `Error("too many files (<n> > <maxFiles>)")` if it exceeds `maxFiles`.
- For each entry: `path` must be a non-empty string and `content` a string, else throw. Validate
  the path with `isSafeRelativePath` (below); throw `Error("unsafe path: <path>")` if it fails.
- `reason` = the value if a string, else `""`.

Export `export function isSafeRelativePath(p: string): boolean` — returns false if `p` is empty,
starts with `/`, contains a backslash, or has any `/`-split segment equal to `..` or `.`;
otherwise true.

### `src/apply.ts` — `applyChanges(targetDir: string, files: FileChange[]): string[]`
For each change: `const abs = resolve(targetDir, file.path)`; `const base = resolve(targetDir)`;
if `abs !== base && !abs.startsWith(base + sep)` throw `Error("path escapes target: <path>")`.
`mkdirSync(dirname(abs), { recursive: true })`, `writeFileSync(abs, file.content, "utf8")`.
Return the list of `file.path` written.

### `src/verify.ts` — `runVerify(targetDir: string, command: string[]): VerifyResult`
If `command.length === 0` return `{ ran: false, ok: true, output: "" }`. Otherwise
`spawnSync(command[0], command.slice(1), { cwd: targetDir, encoding: "utf8" })`; `output =
(res.stdout ?? "") + (res.stderr ?? "")`; `ok = res.status === 0`; return `{ ran: true, ok, output }`.
(Use `node:child_process` `spawnSync`.)

### `src/executor.ts` — `class Executor`
Constructor `(router: ModelRouter, opts: ExecutorOptions = {})`.
- `async run(task: ExecTask, ctx: ExecContext): Promise<ExecResult>`:
  `messages = buildExecutorMessages(task, ctx.context ?? "")`;
  `res = await router.complete({ tier: opts.tier ?? "sonnet", messages })`;
  `{ files, reason } = parseChanges(res.text, opts.maxFiles ?? 50)`;
  `applied = applyChanges(ctx.targetDir, files)`;
  `verify = runVerify(ctx.targetDir, opts.verifyCommand ?? [])`;
  return `{ taskId: task.id, files: applied, reason, verify }`.

### `src/cli.ts` (bin `flow-exec`; first line `#!/usr/bin/env node`)
- `targetDir = process.argv[2]`; `instruction = process.argv.slice(3).join(" ").trim()`. If either
  is missing → stderr `usage: flow-exec <targetDir> <instruction>` and exit 1.
- `router = routerFromEnv()`.
- `verifyCommand = (process.env.FLOW_EXEC_VERIFY ?? "").split(/\s+/).filter((s) => s.length > 0)`.
- Optional context: if `process.env.FLOW_EXEC_CONTEXT_ROOT` is set, build
  `ContextEngine.index(root).assemble({ query: instruction, tokenBudget: 4000 })` and join the
  items' snippets (each prefixed with its path) into the context string; else no context.
- `result = await new Executor(router, { verifyCommand }).run({ id: "cli", instruction }, { targetDir, context })`.
- Print `JSON.stringify(result, null, 2)` to stdout. Catch → stderr stack, exit 1.

### `src/index.ts`
Re-export everything from types, `buildExecutorMessages`, `parseChanges`, `isSafeRelativePath`,
`applyChanges`, `runVerify`, `Executor`.

## Tests (vitest) — no network, temp dirs via `mkdtempSync`
### `test/parse.test.ts`
- parses a valid response; parses one embedded in prose; `reason` defaults to `""`; throws on
  non-JSON, on a missing/!array `files`, on exceeding `maxFiles`, on a non-string path/content.
- `isSafeRelativePath`: true for `a/b.ts`; false for `/abs`, `../x`, `a/../b`, `a\\b`, ``.

### `test/apply.test.ts`
- writes nested files into a temp dir and returns their paths; the content round-trips.
- `applyChanges` throws for a change whose path resolves outside the target (e.g. craft
  `{ path: "../escape.txt" }` and assert it throws — the containment guard, independent of parse).

### `test/verify.test.ts`
- empty command → `{ ran: false, ok: true }`. `["node","-e","process.exit(0)"]` → `ok: true`,
  `ran: true`. `["node","-e","process.exit(1)"]` → `ok: false`. Output is captured.

### `test/executor.test.ts` (scripted `FakeProvider`)
- Provider scripts `{"files":[{"path":"hello.txt","content":"hi"}],"reason":"done"}`; run with a
  temp `targetDir` and `verifyCommand: ["node","-e","process.exit(0)"]` → `files` is
  `["hello.txt"]`, the file exists with content `hi`, `verify.ok` is true, `reason` is `done`.
- A variant with `verifyCommand: ["node","-e","process.exit(1)"]` → `verify.ok` is false.
