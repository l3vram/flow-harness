# Plan v0.6.2 — executor can EDIT existing files (safe search/replace)

Self-contained execution plan. Cold context assumed.

**Repo:** `/Volumes/ExtSSD/mac-storage/projects/flow-harness` — git, npm workspaces, TS ESM
`NodeNext` (explicit `.js` import specifiers), `strict` + `noUncheckedIndexedAccess`, Node 22.

**Goal:** the executor today only writes full new files (`<<<FILE>>>` blocks) — it cannot modify
existing code, which is most of real development. Add an **EDIT** block (safe, exact search/replace)
so it can change existing files, while keeping the CREATE block. Preserve all security.

## The two block formats
Create/overwrite a whole file (existing behavior):
```
<<<FILE relative/path>>>
full file content
<<<END>>>
```
Edit part of an existing file (NEW):
```
<<<EDIT relative/path>>>
<<<SEARCH>>>
exact text that currently exists (may span lines)
<<<REPLACE>>>
new text
<<<END>>>
```
Multiple edits to one file = multiple `<<<EDIT>>>` blocks (applied in order).

## `src/types.ts`
Replace `FileChange` with a discriminated union:
```
export interface WriteChange { kind: "write"; path: string; content: string; }
export interface EditChange { kind: "edit"; path: string; search: string; replace: string; }
export type Change = WriteChange | EditChange;
```
`ExecResult.files` stays `string[]` (the paths touched). Update `parseChanges`/`applyChanges` types
accordingly. Keep `isSafeRelativePath` (currently in parse.ts) exactly as is.

## `src/parse.ts` — `parseChanges(text, maxFiles = 50): { changes: Change[]; reason: string }`
Keep `isSafeRelativePath` unchanged. Rewrite the parser to produce `Change[]`:
- On a line matching `^<<<FILE\s+(.+?)>>>\s*$`: collect following lines until `^<<<END>>>\s*$`;
  push `{ kind: "write", path, content: <joined with "\n"> }`.
- On a line matching `^<<<EDIT\s+(.+?)>>>\s*$`: the next non-consumed markers must be
  `^<<<SEARCH>>>\s*$`, then collect lines until `^<<<REPLACE>>>\s*$` (that's `search`), then collect
  lines until `^<<<END>>>\s*$` (that's `replace`); push `{ kind: "edit", path, search, replace }`.
  If the SEARCH/REPLACE/END structure is malformed, throw `Error("malformed EDIT block for <path>")`.
- `<<<REASON>>> ...` → `reason` (first match; default `""`).
- Throw `Error("executor returned no file blocks")` if zero changes; throw the too-many-files error
  if `changes.length > maxFiles`. Validate every change's `path` with `isSafeRelativePath` (throw
  `unsafe path: <path>`).

## `src/apply.ts` — `applyChanges(targetDir, changes: Change[]): string[]`
Keep the containment guard: for each change, `abs = resolve(targetDir, change.path)`; if
`abs !== resolve(targetDir) && !abs.startsWith(resolve(targetDir) + sep)` throw
`path escapes target: <path>`. Then:
- `write`: `mkdirSync(dirname(abs), {recursive:true})`, `writeFileSync(abs, change.content, "utf8")`.
- `edit`: the file MUST already exist (`existsSync(abs)`), else throw `cannot edit missing file: <path>`.
  Read it; count occurrences of `change.search`; it must occur **exactly once** — if zero throw
  `search text not found in <path>`, if more than one throw `search text is not unique in <path>`
  (this is the safety rule: never guess which occurrence). Replace that one occurrence with
  `change.replace`; write the file back.
Return the list of touched paths (unique, in first-seen order).

## `src/prompt.ts`
Update the system prompt to describe BOTH formats (the two blocks above), verbatim shapes, and add:
"To modify an existing file, prefer an EDIT block; the SEARCH text must match the current file
content exactly and be unique. To create a new file, use a FILE block with its full content. Every
path MUST be relative and never contain `..`. Do not wrap the output in JSON or code fences."

## `src/executor.ts`
Only the destructuring changes: `const { changes, reason } = parseChanges(res.text, this.opts.maxFiles ?? 50);`
then `const files = applyChanges(ctx.targetDir, changes);`. Return shape unchanged
(`{ taskId, files, reason, verify }`).

## Tests
### `test/parse.test.ts`
- parses a FILE block → one `write` change with exact multi-line content.
- parses an EDIT block → one `edit` change with the exact `search` and `replace` (multi-line,
  incl. braces/quotes round-trip).

- throws on no blocks, on an unsafe path (`<<<EDIT ../x>>>`…), on a malformed EDIT (missing REPLACE).

### `test/apply.test.ts`

- edit: seed a file in a temp dir, apply an edit whose SEARCH matches once → the file content is
  updated exactly.
- edit missing file → throws `cannot edit missing file`.
- edit whose SEARCH is not present → throws `not found`.
- edit whose SEARCH appears twice → throws `not unique`.
- containment guard: a change with path `../escape` throws.
