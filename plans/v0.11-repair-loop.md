# Plan v0.11 — repair loop: retry a failed task by feeding the error back to the executor

Self-contained execution plan. Cold context assumed.

**Repo:** `/Volumes/ExtSSD/mac-storage/projects/flow-harness` — git, npm workspaces, TS ESM
`NodeNext` (explicit `.js` import specifiers), `strict` + `noUncheckedIndexedAccess`, Node 22.

**Goal:** today a task whose verify fails just goes `blocked`. Now that the executor can EDIT
existing files (v0.6.2), give it a bounded chance to FIX its own failure: when verify fails, retry
the executor with the verify output and the current file contents appended to its context, so it
edits the files until verify passes or the repair budget is exhausted.

## `src/orchestrator.ts`
Import `readFileSync, existsSync` from `node:fs` and `join` from `node:path`.

In the dispatch loop, replace the single `executor.run(...)` + status logic with a repair loop.
Keep the `setStatus(taskId, "running")` call once, before the loop. Then:
```
const baseContext = this.contextFor(spec.instruction);
const maxTries = (this.opts.maxRepairAttempts ?? 2) + 1;
let result = await this.executor.run(
  { id: taskId, instruction: spec.instruction },
  { targetDir: this.opts.targetDir, context: baseContext },
);
let tries = 1;
while (!result.verify.ok && tries < maxTries) {
  const repair = this.repairContext(result.files, result.verify.output);
  result = await this.executor.run(
    { id: taskId, instruction: spec.instruction },
    { targetDir: this.opts.targetDir, context: baseContext + "\n\n" + repair },
  );
  tries++;
}
```
Then the existing risk + status logic on the final `result` (unchanged), and record
`attempts: tries` in the outcome:
```
const ok = result.verify.ok;
const risk = assessRisk({
  filesChanged: result.files,
  verifyFailed: !ok,
  touchesSecurity: result.files.some((f) => /auth|secret|password|token|crypt|exec|spawn/i.test(f)),
});
let status: "green" | "blocked" | "review";
if (!ok) status = "blocked";
else if (risk.level === "high") status = "review";
else status = "green";
const reason = !ok ? "verify failed" : status === "review" ? "high risk — needs human review" : "";
this.runtime.setStatus(taskId, status, reason);
outcomes[taskId] = { status, files: result.files, verify: result.verify, reason: result.reason, risk, attempts: tries };
```

Add a private method:
```
private repairContext(files: string[], verifyOutput: string): string {
  const shown = files.map((f) => {
    const abs = join(this.opts.targetDir, f);
    const content = existsSync(abs) ? readFileSync(abs, "utf8") : "(missing)";
    return `--- ${f} ---\n${content}`;
  });
  return [
    "The previous attempt did not pass verification.",
    "",
    "Verify output:",
    verifyOutput,
    "",
    "Current content of the files you changed:",
    shown.join("\n\n"),
    "",
    "Fix the problem by EDITing the file(s) so verification passes.",
  ].join("\n");
}
```
(The repair loop's `tries` counter is internal to one dispatch; do NOT call `setStatus("running")`
per try — a single `running` per dispatch is correct, and this keeps the runtime's 3-attempt circuit
breaker for the separate cross-dispatch case.)
