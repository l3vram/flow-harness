# v0.20 — wire QA into the orchestrator (the deep dogfood) — self-built

Make the autonomous loop verify tasks with `@flow/qa` and let its **tickets** drive the repair loop —
so `flow-run` accepts a task only when QA says `complete`, with evidence, not on a single verify command's
exit code. Backward compatible: a task with no criteria behaves exactly as today.

## Behavior
A `TaskSpec` may now carry **acceptance criteria**. In `Orchestrator.run()`, for a task that has criteria:
1. the executor writes the files **without** a redundant verify command (`verifyCommand: []`);
2. the orchestrator runs `runQA({ target: targetDir, platform, criteria })` — QA is the verification of record;
3. `ok = report.complete`; on failure the **repair loop** feeds the QA **tickets** (severity, criterion, symptom,
   repro) back to the executor, bounded by `maxRepairAttempts`, then blocks — same convergence machinery, but
   driven by evidence-backed tickets instead of raw command output;
4. the QA report is attached to the task's outcome.
A task with no criteria uses its `verify` command exactly as before.

Evidence goes to `@flow/qa`'s default temp dir (NOT under `targetDir`), so a self-build run never dirties the
repo's working tree.

## Files
1. `packages/orchestrator/package.json` — add `"@flow/qa": "*"` to `dependencies` (its `node_modules` symlink
   already exists). 2. `packages/orchestrator/tsconfig.json` — add `{ "path": "../qa" }` to `references`.
3. `packages/orchestrator/src/types.ts` — `import type { Criterion, QAReport } from "@flow/qa";`; add
   `criteria?: Criterion[]` and `platform?: string` to `TaskSpec`; add `qa?: QAReport` to `TaskOutcome`.
   (`RunConfig.tasks` is `TaskSpec[]`, so `flow-run` configs can specify criteria per task for free.)
4. `packages/orchestrator/src/orchestrator.ts` — `import { runQA, type QAReport } from "@flow/qa";`; in the task
   loop compute `hasCriteria`, pass `verifyCommand: hasCriteria ? [] : spec.verify` to the executor, run
   `runQaFor(spec)` after each attempt when `hasCriteria`, set `ok = qa.complete`, and use a new `qaSignal(report)`
   (renders failing tickets) as the repair signal; record `qa` in the outcome; reason `"QA not complete"` on a
   QA block. Add two private helpers: `runQaFor(spec): QAReport` and `qaSignal(report): string`.
5. `packages/orchestrator/test/orchestrator.test.ts` — +2 tests: (a) a task with a passing criterion
   (`node -e process.exit(0)`) → `green`, `outcome.qa.complete === true`, attempts 1; (b) a failing criterion
   (`process.exit(1)`, severity `critical`) → run not complete, task `blocked`, `outcome.qa.complete === false`,
   and at least one ticket with severity `critical`.
