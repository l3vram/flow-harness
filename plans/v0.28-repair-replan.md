# v0.28 — repair→replan: the CEO diagnoses a blocked task and replans — self-built

The pieces exist: a task that exhausts its repair budget becomes `blocked` (v0.11 circuit breaker), and the
CEO can extend the DAG (`add_task`, v0.26). What's missing to turn "repair → blocked → dead end" into
"repair → diagnose → replan" is (a) letting the CEO **see the failure diagnosis** and (b) **prompting** it to
replan on a blocked task instead of just stopping. This increment wires exactly that.

## Changes — `packages/ceo/src/prompt.ts`
- **Surface the diagnosis**: add `reason: p.reason ?? ""` to each task in the state snapshot the CEO receives
  (it already carries id/role/tier/status/deps). `reason` holds the block/verify diagnosis (e.g. "verify failed",
  "QA not complete", the circuit-breaker note).
- **Prompt to replan**: add to the system prompt — "When a task is `blocked` (its repair budget is exhausted),
  read its `reason` to diagnose the failure, then either `add_task` a remediation task that addresses the blocker,
  or `await_human` if it truly needs a person. Do not `complete` while critical work is blocked."

## Tests
- `packages/ceo/test/replan.test.ts` (new): `buildDecisionMessages` for a state with a blocked task puts that
  task's `reason` into the user message; the system prompt mentions blocked/replanning (`add_task`).
- `packages/orchestrator/test/orchestrator.test.ts` (+1): repair→replan **end to end** — task "a" always fails
  verify and exhausts its repair budget → `blocked`; a scripted CEO then `add_task`s a remediation "a-fix" (with a
  passing per-task verify), dispatches it → "a-fix" goes green. Demonstrates the loop: exhausted → replan → green.

## Done criteria
`npm test` green (168 → 171); existing CEO/orchestrator tests unchanged; no new deps. The snapshot change is
additive (a FakeProvider ignores content, so `ceo.test.ts` is unaffected).

## Out of scope (follow-ups)
`split` / `replace` / `invalidate` a task; an explicit "diagnose" LLM step that summarises tickets before replanning;
a replan budget/ceiling separate from `maxSteps`.
