# v0.17 — executor robustness (self-built)

Two gaps surfaced while the harness built v0.16 of itself. Close both in `@flow/executor`.

## 1. Atomic apply — no partial writes

`applyChanges` (`packages/executor/src/apply.ts`) writes each change to disk as it iterates, so a
batch that fails on a later change leaves the earlier ones on disk — a half-modified, often
non-compiling tree that poisons the repair retry. Make it **atomic**:

- **Pass 1** — validate every change and fold it into an in-memory working copy, writing nothing.
  Keep all existing rules: path containment (`path escapes target`), edits require an existing file
  (`cannot edit missing file`), and the search text must occur **exactly once** (`search text not
  found` / `search text is not unique`). Edits read from the running in-memory copy, so multiple
  edits to the same file compose in order.
- **Pass 2** — only after the whole batch validates, write every touched file (mkdir -p first).
- Return the touched paths, de-duplicated, in first-touched order (unchanged contract).

A failure now throws before any write → nothing is persisted.

## 2. A total provider failure blocks the task, it does not abort the run

`Executor.run` (`packages/executor/src/executor.ts`) calls `router.complete` unguarded; when every
provider for the tier (primary + fallback) fails, the throw escapes and kills the whole orchestrated
run. Wrap it: on failure, return a failed `verify` result (`ran:true, ok:false, output:"llm request
failed: <msg>"`, `files:[]`). The orchestrator's repair loop then blocks the task after its budget
and moves on to siblings — no crash. (The apply-failure catch from v0.16 stays as-is.)

## Files
- `packages/executor/src/apply.ts` — atomic two-pass rewrite (behavior-compatible for all existing tests).
- `packages/executor/src/executor.ts` — guard `router.complete`.
- `packages/executor/test/apply.test.ts` — add: a failing change in a batch writes none of it (atomicity);
  multiple edits to one file apply in order.
- `packages/executor/test/executor.test.ts` — add: a throwing router yields a failed verify, not a throw.
