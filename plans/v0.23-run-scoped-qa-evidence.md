# v0.23 — run-scoped QA evidence — self-built

Closes the QA loop's evidence story: QA evidence produced during an autonomous run now lands under the
run's own directory (auditable, inspectable), instead of a random temp dir. Small, deterministic, offline.

## What
- `OrchestratorOptions` gains `evidenceDir?: string` — the base dir for run-scoped QA evidence.
- `Orchestrator.runQaFor` passes `{ evidenceDir: join(opts.evidenceDir, spec.id) }` to `runQA` when the base is
  set (each task's evidence under `<evidenceDir>/<taskId>/`); otherwise the previous temp-dir default (unchanged).
- `flow-run` (cli.ts) sets `evidenceDir: join(dir, "evidence")` where `dir = <FLOW_HOME>/runs/<runId>`, so a real
  run collects all its QA evidence under the run.

## Files
1. `packages/orchestrator/src/types.ts` — add `evidenceDir?: string` to `OrchestratorOptions`.
2. `packages/orchestrator/src/orchestrator.ts` — `runQaFor` uses `this.opts.evidenceDir` (join with `spec.id`) when set.
   `join` is already imported.
3. `packages/orchestrator/src/cli.ts` — add `evidenceDir: join(dir, "evidence"),` to the `Orchestrator` options
   (`dir` and `join` are already in scope).
4. `packages/orchestrator/test/orchestrator.test.ts` — +1 test: a QA-criteria task with `opts.evidenceDir` set →
   `outcome.qa.evidenceDir` is under `<evidenceDir>/<taskId>`.
