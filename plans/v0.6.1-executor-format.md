# Plan v0.6.1 — robust executor output format (file-block markers)

Self-contained execution plan. Cold context assumed.

**Repo:** `/Volumes/ExtSSD/mac-storage/projects/flow-harness` — git, npm workspaces, TS ESM
`NodeNext` (explicit `.js` import specifiers), `strict` + `noUncheckedIndexedAccess`, Node 22.

**Problem:** the executor currently asks the model for a JSON object whose file `content` is a
JSON string. For multi-line, multi-file output, models emit raw newlines/quotes inside those
strings → invalid JSON → `parseChanges` throws "executor returned no parseable JSON". Verified
end-to-end: single short files work; a real multi-file package build fails.

**Fix:** replace the JSON patch format with a **file-block marker format** that needs no escaping
of content. Change only the model-facing format (prompt + parser) and the tests that craft
executor responses. **Keep all security behavior identical.**

## The format
Each file is a block:
```
<<<FILE relative/path/from/root>>>
...full file content, verbatim, any number of lines...
<<<END>>>
```
One block per file. After the last block an optional single line: `<<<REASON>>> one sentence`.

### `src/prompt.ts` — system message content, verbatim
```
You are an implementation executor. You are given a task and optionally some relevant repository
context. Produce the complete new contents of every file needed to accomplish the task. Output
each file as a marker-delimited block, and nothing else:
<<<FILE relative/path/from/root>>>
the full, verbatim file content (any number of lines)
<<<END>>>
Repeat one block per file. After the last block you may add a single line:
<<<REASON>>> one short sentence
Every path MUST be relative to the project root, use forward slashes, and never contain "..".
Do not wrap the output in JSON or code fences. Provide the FULL content of each file, not a diff.
```
The user message is unchanged: `` `Task: ${task.instruction}` `` plus, when context is non-empty,
`` `\n\nRelevant context:\n${context}` ``.

### `src/parse.ts` — the parser
Keep `isSafeRelativePath` unchanged. Rewrite `parseChanges`:
- Split `text` into lines (`text.split("\n")`).
- Walk the lines. When a line matches `^<<<FILE\s+(.+?)>>>\s*$`, take the captured path (trimmed);
  then collect every subsequent line until a line matching `^<<<END>>>\s*$`; the file content is
  those collected lines joined with `"\n"`. Push `{ path, content }`. (A `<<<FILE>>>` with no
  closing `<<<END>>>` before end-of-input: ignore that trailing partial block.)
- After collecting, a line matching `^<<<REASON>>>\s?(.*)$` gives `reason` (first match; trimmed);
  default `""`.
- If **no** complete file block was found, throw `Error("executor returned no file blocks")`.
- If the number of blocks exceeds `maxFiles`, throw `Error("too many files (<n> > <maxFiles>)")`.
- For every block, if `!isSafeRelativePath(path)` throw `Error("unsafe path: <path>")`.
- Return `{ files, reason }`.

## Tests
### `test/parse.test.ts` (rewrite)
- parses a single block into one `FileChange` with the exact content.
- parses **two** blocks where a content body spans multiple lines and includes braces, quotes and
  a blank line — assert the content round-trips exactly (this is the whole point).
- extracts `<<<REASON>>> ...`; defaults `reason` to `""` when absent.
- throws "no file blocks" when the text has none.
- throws on an unsafe path (`<<<FILE ../evil.txt>>>` … `<<<END>>>`).
- throws when block count exceeds a small `maxFiles`.
- `isSafeRelativePath` cases unchanged: true for `a/b.ts`; false for `/abs`, `../x`, `a/../b`,
  `a\\b`, and the empty string.

### `test/executor.test.ts` (update responses only)
Replace each scripted JSON response with a block-format string, e.g.
`` `<<<FILE hello.txt>>>\nhi\n<<<END>>>\n<<<REASON>>> done` ``. Keep the assertions: the file is
written with content `hi`, `verify.ok` reflects the configured command, `reason` is `done`.

### `packages/orchestrator/test/orchestrator.test.ts` (helper only)
Change `execRouter(files)` so its `FakeProvider` returns block-format text:
`files.map(f => "<<<FILE " + f.path + ">>>\n" + f.content + "\n<<<END>>>").join("\n") + "\n<<<REASON>>> done"`.
Leave every test case and every other helper unchanged.
