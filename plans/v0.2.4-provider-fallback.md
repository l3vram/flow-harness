# Plan v0.2.4 — provider fallback (auto-switch a tier to a backup on failure)

Self-contained execution plan. Cold context assumed.

**Repo:** `/Volumes/ExtSSD/mac-storage/projects/flow-harness` — git, npm workspaces, TS ESM
`NodeNext` (explicit `.js` import specifiers), `strict` + `noUncheckedIndexedAccess`, Node 22.

**Goal:** each tier can have a PRIMARY provider/model and an optional FALLBACK. If the primary's
`complete()` throws (saturation/rate limit after retries, outage), the router automatically tries
the fallback. This makes inference resilient and lets e.g. Gemini(CEO) fall back to Mistral, or
Groq(exec) fall back to Mistral `codestral`. Backward compatible: no fallback configured → today's
single-provider behaviour.

## Design (backward-compatible)
`routerFromEnv` builds, per tier, the primary `ModelProfile` (as today) and — when fallback env is
set — a SECOND `ModelProfile` for the same tier (a chain). `ModelRouter.resolve(tier)` keeps
returning the FIRST matching profile (unchanged). `ModelRouter.complete(req)` collects ALL profiles
for the tier in order and tries each until one succeeds.

## Scope — touch ONLY `packages/llm`
`src/router.ts`, `src/config.ts`, `test/router.test.ts` (+ maybe a small test helper). Do not change
`types.ts`, the providers, or other packages.

## `src/router.ts`
- Keep the constructor `(providers: Map<string, LLMProvider>, profiles: ModelProfile[], defaultTier)`
  and `resolve(tier)` EXACTLY as today (first matching profile; used by existing tests).
- Add a private helper `chain(tier): { provider: LLMProvider; model: string }[]` — all profiles whose
  `tier` matches (in array order), each resolved to its provider instance (throw if a provider name
  isn't registered); if none match, fall back to the `defaultTier`'s chain, else the first profile.
- Rewrite `complete(req)`:
  ```
  const tier = req.tier ?? this.defaultTier;
  const entries = this.chain(tier);
  let lastErr: unknown;
  for (const entry of entries) {
    try {
      return await entry.provider.complete({
        model: req.model ?? entry.model,
        messages: req.messages,
        maxTokens: req.maxTokens,
        temperature: req.temperature,
      });
    } catch (err) { lastErr = err; }
  }
  throw lastErr ?? new Error(`no provider succeeded for tier '${tier}'`);
  ```
  (If `req.model` is set it applies to every entry — that matches today's single-entry behaviour;
  keep it.)

## `src/config.ts`
For each tier `t` (U = uppercase), after building the primary profile (unchanged), also read a
fallback: `FLOW_LLM_<U>_FALLBACK_PROVIDER` (+ `_FALLBACK_MODEL`, `_FALLBACK_API_KEY`,
`_FALLBACK_BASE_URL`). If a fallback provider kind is present, build that provider with `makeProvider`
(reuse it), register it in the map under a distinct key (e.g. `t + "-fallback"`), and push a SECOND
`ModelProfile` `{ tier: t, provider: <that key>, model: fallbackModel ?? defaultModel(kind, t) }`
AFTER the primary. Fallback creds/baseUrl come only from the `_FALLBACK_*` vars (no cross-fallback to
the primary's). Providers are keyed by `t` (primary) and `t + "-fallback"` (fallback).
