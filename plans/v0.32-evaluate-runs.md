# v0.32 — evaluate every run: attach an EvaluationReport to the RunReport — self-built

Wire the v0.30 evaluation engine into the loop so every autonomous run **self-scores**. Deterministic; makes
`@flow/eval` actually used and is the foundation for learning/comparing versions.

## New helper — `packages/orchestrator/src/evaluate-run.ts`
`evaluateRunReport(report: RunReport): EvaluationReport` — builds an `EvalInput` from the report and calls
`@flow/eval`'s `evaluate`:
- `tasksTotal/Green/Blocked/Review` from `report.tasks[].status`.
- `criteriaTotal/criteriaPassed` by summing each outcome's `qa.criteria` (a criterion counts as passed when
  `status === "pass"`).
- `criticalTickets` = QA tickets with `severity` `high` or `critical`.
- `attempts` = sum of each outcome's `attempts` (default 1).

## Wiring
- `packages/orchestrator/src/types.ts`: `RunReport` gains `evaluation?: EvaluationReport` (import type from `@flow/eval`).
- `packages/orchestrator/src/orchestrator.ts`: at the end of `run()`, build the report object, set
  `report.evaluation = evaluateRunReport(report)`, and return it.
- `packages/orchestrator/src/index.ts`: export `evaluateRunReport`.
- `package.json` + `tsconfig.json`: add `@flow/eval` (create its `node_modules` symlink first — v0.19 lesson;
  `@flow/eval` has no deps).

## Tests (offline)
- `packages/orchestrator/test/evaluate-run.test.ts` (new): `evaluateRunReport` on a synthetic report (2 green tasks,
  a QA report with 2/2 criteria passed) scores 100; a report with a blocked task + a failed criterion + a critical
  ticket scores lower and reflects it.
- `packages/orchestrator/test/orchestrator.test.ts` (+1): after a run, `report.evaluation` is present with a numeric
  `score` and the five dimensions.
