# v0.18 — `@flow/qa` (Layer A: deterministic suites) — self-built

First increment of the QA engine, per [ADR 0007](../docs/decisions/0007-qa-independent-capability.md):
an **independent** capability (pure lib `@flow/qa` + bin `flow-qa`), **run-less**, **contract-first**,
fully **offline/deterministic** (no network, no browser, no LLM). It runs an explicit verification
command per acceptance criterion, captures evidence artifacts to disk, and emits a QA report with error
tickets. It emits evidence/verdicts/tickets — never decisions. Layer B (Playwright web), mobile, the
`flow_qa` MCP tool, and orchestrator wiring are later increments.

## The contract (schema — `packages/qa/src/types.ts`)

```ts
export type Status = "pass" | "fail" | "pending";

export interface Criterion {
  id: string;
  description: string;
  verify: string[];              // argv run in `target` (spawnSync, no shell). [] => pending.
  severity?: "low" | "medium" | "high" | "critical";  // ticket severity on fail; default "high"
  tags?: string[];               // propagated to the ticket
}
export interface QARequest { target: string; platform: string; criteria: Criterion[]; }

export interface EvidenceRef { kind: string; path: string; }  // artifact written to disk
export interface Ticket {
  id: string; criterionId: string; severity: string; symptom: string; evidence: EvidenceRef[];
  location?: string;             // file:line / selector — best-effort; unset in Layer A
  repro?: string[];              // the verify argv (minimal repro)
  tags?: string[];
}
export interface CriterionResult {
  id: string; description: string; status: Status; evidence: EvidenceRef[]; tickets: Ticket[];
}
export interface QAReport {
  target: string; platform: string; criteria: CriterionResult[];
  summary: string; complete: boolean; evidenceDir: string;
}
```

## Engine — `packages/qa/src/qa.ts`

`export function runQA(req: QARequest, opts?: { evidenceDir?: string }): QAReport`

- `evidenceDir = opts?.evidenceDir ?? mkdtempSync(join(tmpdir(), "flow-qa-"))`. (Tests inject it for
  determinism.)
- For each criterion:
  - `dir = join(evidenceDir, criterion.id)`; `mkdirSync(dir, { recursive: true })`.
  - If `verify.length === 0` → `status: "pending"`, no evidence, no ticket.
  - Else run `spawnSync(cmd, args, { cwd: req.target, encoding: "utf8" })` (reuse the pattern in
    `packages/executor/src/verify.ts`). Write `stdout.txt`, `stderr.txt`, `exit.txt` (String(status)) into
    `dir`; `evidence = [{kind:"stdout",path},{kind:"stderr",path},{kind:"exit",path}]`.
  - `ok = res.status === 0`; `status = ok ? "pass" : "fail"`.
  - On `fail`, synthesize exactly one ticket: `{ id: `${id}-fail`, criterionId: id, severity: criterion.severity ?? "high",
    symptom: <first non-empty line of stderr, else stdout, else "exit "+status/res.error.message>, evidence,
    repro: [criterion.verify.join(" ")], ...(criterion.tags ? { tags } : {}) }`. Leave `location` unset (Layer A).
- `complete = criteria.length > 0 && every result.status === "pass"`.
- `summary = `${passCount}/${criteria.length} pass``.
- Deterministic: no clock/network/LLM in the report values; only the injected `evidenceDir` and file paths.

## Bin — `packages/qa/src/cli.ts`
`flow-qa <target> <request.json>` where `request.json = { platform?: string, criteria: Criterion[] }`.
Build `QARequest { target: argv[2], platform: json.platform ?? "node", criteria: json.criteria }`, call
`runQA`, `console.log(JSON.stringify(report, null, 2))`, `process.exit(report.complete ? 0 : 1)` — so it is a
drop-in system verifier for CI or another CLI. Shebang `#!/usr/bin/env node`.

`packages/qa/src/index.ts`: `export * from "./types.js"; export * from "./qa.js";`

## Tests — `packages/qa/test/qa.test.ts` (offline, inject `evidenceDir` = a temp dir)
1. all criteria pass (`verify: ["node","-e","process.exit(0)"]` ×2) → `complete: true`, no tickets, `summary` "2/2 pass",
   and the stdout/stderr/exit evidence files exist on disk.
2. a failing criterion (`["node","-e","process.exit(1)"]`, `severity:"critical"`, `tags:["regression"]`) → its
   `status:"fail"`, exactly one ticket with `criterionId`, `severity:"critical"`, `repro` = the command, `tags:["regression"]`,
   non-empty `evidence`; report `complete:false`.
3. an empty-`verify` criterion → `status:"pending"` and `complete:false`.
4. determinism/evidence: `exit.txt` for a failing criterion contains "1".
