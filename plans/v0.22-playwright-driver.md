# v0.22 — `@flow/qa` Layer B: the real Playwright driver — supervisor-built

Completes Layer B: a `WebDriver` backed by a real browser, so `runWebQA` verifies a running web app with
real evidence. Built by hand (not an auto-build) because a browser binary can't live in the offline `npm test`.

## What
- `packages/qa/src/playwright-driver.ts` — `PlaywrightDriver implements WebDriver`. It loads Playwright through a
  **non-literal dynamic import** (`const name = "playwright"; await import(name)`), so `tsc` needs no build-time
  dependency and the offline suite runs without playwright or any browser. Missing playwright → a clear, actionable
  error on first navigation. Captures console + network via `page.on(...)`, real screenshots via `page.screenshot`.
- `packages/qa/src/index.ts` — export the driver.
- `packages/qa/package.json` — `playwright` as an **optionalDependency** (`^1.63.0`); installed with
  `npm i playwright && npx playwright install chromium`.
- `packages/qa/smoke/playwright-smoke.mjs` — a runnable live-browser smoke (NOT in the vitest suite): serves a tiny
  page, drives it with `PlaywrightDriver` + `runWebQA`, asserts a passing criterion and a failing one (ticket +
  failure screenshot).

## Verification (done)
- Offline suite unchanged: **156/156** (the driver is never instantiated there).
- **Live smoke passed**: real Chromium drove the page → `home` pass (screenshot captured), `missing` fail (ticket +
  `failure.png`), `summary: 1/2 pass`, `complete: false`, exit 0.

## Why no vitest test for the driver
A real browser can't run in the deterministic offline suite (needs binaries, is slow/flaky). The driver is a thin
structural adapter, covered by the live smoke; the web-QA logic itself is covered offline by `FakeWebDriver` (v0.21).

## Out of scope
Launching an app (dev server) from QA; deriving web criteria from the planner's acceptance; wiring web QA through
the orchestrator (web criteria already return the same `QAReport`, so the wiring mirrors v0.20).
