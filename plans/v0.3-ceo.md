# Plan v0.3 — `@flow/ceo` (thin executive loop)

Self-contained execution plan. Cold context assumed; everything is here.

**Repo:** `/Volumes/ExtSSD/mac-storage/projects/flow-harness` — git, npm workspaces, TS ESM
`NodeNext` (explicit `.js` import specifiers), `strict` + `noUncheckedIndexedAccess`, Node 22.
Study `packages/core/src` and `packages/llm/src` for style and the exact exported APIs.

**Goal:** the first, deliberately *thin* executive ("CEO"). It observes a run's state and asks
the LLM for the single next move as structured JSON, then applies only DAG-safe actions. It
**never writes or edits code**, never mutates state except through `@flow/core`'s typed methods,
and keeps humans in the loop for anything risky. Fully testable with the `FakeProvider` (no key).

Create `packages/ceo` = `@flow/ceo` (`type: module`, bin `flow-ceo`). Deps: `@flow/core`,
`@flow/llm` (workspace `*`). No external runtime deps.

## Files

### `src/types.ts`
```
export type CeoAction = "dispatch" | "advance" | "await_human" | "complete";
export const CEO_ACTIONS: readonly CeoAction[] = ["dispatch","advance","await_human","complete"];
export interface CeoDecision {
  action: CeoAction;
  taskIds: string[];   // ids to run for "dispatch"; [] otherwise
  reason: string;      // one short sentence
  confidence: number;  // 0..1, MODEL-REPORTED — never trusted for an automatic risk decision
}
```

### `src/prompt.ts` — `buildDecisionMessages(state: State, ready: string[]): Message[]`
Return exactly two messages. The **system** message content is this exact text:

```
You are the executive (CEO) of an autonomous software-engineering run. You decide the single
next move. You never write or edit code, and you never invent state. You are given a JSON
snapshot of the run. Choose exactly one action:
- "dispatch": run the listed ready tasks now (only ids present in `ready`).
- "advance": move to the next wave (only when the current wave is fully green or blocked).
- "await_human": pause for a human decision (ambiguity, risk, or a needed gate).
- "complete": the objective is met and every task is green.
Reply with ONLY a JSON object, no prose, of exactly this shape:
{"action":"dispatch|advance|await_human|complete","taskIds":["..."],"reason":"one sentence","confidence":0.0}
```

The **user** message content is `JSON.stringify(snapshot)` where `snapshot` is
`{ objective, phase, current_wave, waves, ready, gates, tasks }` and `tasks` maps each plan to
`{ id, role, tier, status, deps }` (omit the runtime-only fields).

### `src/parse.ts` — `parseDecision(text: string): CeoDecision`
Robust: take the substring from the first `{` to the last `}` and `JSON.parse` it; if that fails
or no braces, throw `Error("CEO returned no parseable JSON decision")`. Then:
- `action` must be one of `CEO_ACTIONS`, else throw `Error("invalid CEO action: <x>")`.
- `taskIds` = the value if it is an array of strings, else `[]`.
- `reason` = the value if a string, else `""`.
- `confidence` = the value if a finite number, clamped to `[0,1]`, else `0`.

### `src/ceo.ts` — `class Ceo`
```
export interface CeoOptions { tier?: Tier; autoApply?: boolean; }
```
Constructor `(runtime: Runtime, router: ModelRouter, opts: CeoOptions = {})`.
- `async decide(): Promise<CeoDecision>` — `state = runtime.state`, `ready = runtime.ready()`,
  `messages = buildDecisionMessages(state, ready)`, `res = await router.complete({ tier: opts.tier ?? "opus", messages })`,
  return `parseDecision(res.text)`.
- `async step(): Promise<{ decision: CeoDecision; applied: boolean }>` — `decision = await decide()`.
  Only ONE thing is ever auto-applied, and only when `opts.autoApply` is true: if
  `decision.action === "advance"` **and** `runtime.waveDone()`, call `runtime.advance()` and set
  `applied = true`. Everything else (`dispatch`, `await_human`, `complete`, or an `advance` when
  the wave is not done) applies nothing — those are signals handed back to the caller. Return
  `{ decision, applied }`.
- `async run(maxSteps = 10): Promise<CeoDecision[]>` — loop up to `maxSteps`: push each
  `step()`'s decision; break on `complete` or `await_human`; break on `dispatch` (no executor is
  wired yet — hand the ids to the fleet/human); break on `advance` that did not apply.

Comment clearly that model-reported `confidence` is not used to gate anything automatically —
it is recorded for humans only.

### `src/cli.ts` (bin `flow-ceo`; first line `#!/usr/bin/env node`)
`runId = process.argv[2]`; if missing → stderr `usage: flow-ceo <runId>` and exit 1.
`base = process.env.FLOW_HOME ?? ".flow"`; `dir = join(base, "runs", runId)`;
`runtime = new Runtime(dir)`; if `!runtime.started()` → stderr `run not found: <runId>` exit 1.
`router = routerFromEnv()`. `ceo = new Ceo(runtime, router, { autoApply: process.env.FLOW_CEO_AUTO_APPLY === "1" })`.
`decisions = await ceo.run(Number(process.env.FLOW_CEO_MAX_STEPS ?? 10))`. Print each decision as
a JSON line to stdout. Catch → stderr stack, exit 1.

Re-export everything from types, `buildDecisionMessages`, `parseDecision`, `Ceo`, `CeoOptions`.

## Tests (vitest) — no network
### `test/parse.test.ts`
- parses a clean JSON decision; parses one embedded in surrounding prose; `taskIds` defaults to
  `[]` when missing or not an array; `confidence` clamps `1.5→1`, `-1→0`, non-number `→0`; an

### `test/ceo.test.ts` (use a temp dir via `mkdtempSync`, and a scripted `FakeProvider`)
Helper: `scripted(responses: string[])` returns a responder `() => responses[min(i++, len-1)]`.
Build the router as
`new ModelRouter(new Map([[p.name, p]]), [{ tier:"opus", provider:p.name, model:"m" }], "opus")`.
- `decide()` returns the parsed decision the provider scripts.
- `step()` with `autoApply:true`: seed a run whose single wave-1 task is `green` (so
  `waveDone()` is true), script `"advance"` → `applied` is true and `runtime.state.current_wave`
  becomes 1.
- `step()` with `autoApply:true` but the wave NOT done, script `"advance"` → `applied` is false,
  `current_wave` unchanged.
- `run()` scripting `["dispatch"]` → returns exactly one decision and stops.
- `run()` scripting an `"advance"` (wave done) then `"complete"` → returns two decisions.

Seed runs with `Runtime.init(dir, id, obj)` + `addTask` + `setStatus` from `@flow/core`.
