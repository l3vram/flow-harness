# v0.16 — expose the SDD planner + convergence over MCP

**Goal.** Make the harness able to *plan* and *check convergence* over MCP, not just add tasks and
execute them. Today `@flow/planner` (objective → spec + task DAG) and `@flow/converge`
(plan + outcomes → done-vs-spec report) exist but are **not** reachable from an MCP host. Wire them
in as two new tools. This closes the self-build surface: a host can drive
objective → **spec/plan** → gate → execute → **converge** entirely over MCP.

## Naming (important — avoid a collision)

The MCP tool already named `flow_plan` (`packages/mcp-server/src/tools.ts`) computes **wave layering**
(`runtime.waves()`) — it is *not* the SDD planner. Do **not** rename or reuse it (tests and hosts
depend on it). Add two **new** tools:

- `flow_spec` — run the SDD planner: objective (+ optional context) → `{ spec, approach, tasks }`.
- `flow_converge` — deterministic done-vs-spec report from a plan + task outcomes.

Tool count goes 11 → 13. Every existing tool, including `flow_plan` (waves), stays byte-identical.

## Recon (inlined — do not rediscover)

`@flow/planner` (already built, `packages/planner`):
```ts
class Planner { constructor(router: ModelRouter, opts?: { tier?: string }); // tier defaults to 'opus'
  async plan(objective: string, context?: string): Promise<Plan> }
interface Spec { objective: string; requirements: string[]; acceptance: string[]; clarifications: string[] }
interface PlannedTask { id: string; role: string; tier: string; deps: string[]; instruction: string; verify?: string[] }
interface Plan { spec: Spec; approach: string; tasks: PlannedTask[] }
```
`@flow/converge` (already built, `packages/converge`):
```ts
function converge(plan: Plan, outcomes: Record<string, string>): ConvergenceReport
// outcomes maps taskId -> outcome string; a task counts as done only when its value === 'green'.
interface ConvergenceReport { objective; complete; done; pending; acceptance; clarifications; summary }
```
MCP tool pattern (`packages/mcp-server/src/tools.ts`): each tool is a `ToolDef`
`{ name, description, inputSchema: JsonSchema, handler(ctx: ToolContext, args) }`, pushed onto the
exported `tools` array. `ToolContext = { baseDir: string; router?: ModelRouter }`. Get a router with
`ctx.router ?? routerFromEnv()` (same as `flow_execute`). Use the existing arg extractors
`reqStr` / `optStr`. These two tools are **run-less** — they must NOT call `open()` / touch a Runtime;
they are pure over their inputs (planner calls the LLM; converge is deterministic).

## Files to change

1. `packages/mcp-server/package.json` — add deps `"@flow/planner": "*"`, `"@flow/converge": "*"`.
2. `packages/mcp-server/tsconfig.json` — add project references to `../planner` and `../converge`
   (match how it already references `../executor`, `../llm`, `../core`).
3. `packages/mcp-server/src/tools.ts` — import `Planner` (`@flow/planner`), `converge` + type `Plan`,
   then append two `ToolDef`s:
   - `flow_spec`: input `{ objective: string (required), context?: string, tier?: string }`.
     Handler: `const planner = new Planner(ctx.router ?? routerFromEnv(), tier ? { tier } : undefined);
     return await planner.plan(objective, context);` → returns the `Plan`.
   - `flow_converge`: input `{ plan: object (required, a Plan), outcomes: object (required, map) }`.
     Handler: validate `plan` and `outcomes` are objects, then `return converge(plan as Plan, outcomes)`.
     (Add a small `reqObj(args, key)` extractor, or inline the `typeof === 'object'` guard.)
   Descriptions must say `flow_spec` needs a real LLM backend (FLOW_LLM_*); `flow_converge` is offline.
4. `packages/mcp-server/test/tools.test.ts` — add tests:
   - `flow_spec`: inject `ctx.router` as a stub returning scripted plan JSON (copy the router-stub
     pattern from `packages/planner/test/planner.test.ts`). Assert the returned `spec.objective` and
     `tasks` match. No network.
   - `flow_converge`: build a `Plan` literal with two tasks and pass `outcomes { t1: 'green', t2: 'blocked' }`;
     assert `done=['t1']`, `pending=['t2']`, `complete=false`, and `summary` contains `1/2 green`.

## Done criteria (deterministic, blocking)

- `npm test` (i.e. `tsc -b && vitest run`) passes with the new tests included.
- `getTool('flow_spec')` and `getTool('flow_converge')` resolve; `tools.length === 13`.
- `flow_plan` still returns wave layering (unchanged); no existing test edited except additive.

Persisting a spec/plan into a run's event log; a `flow_plan_execute` that registers planned tasks;
